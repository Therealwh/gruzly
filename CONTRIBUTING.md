# Contributing to Gruzly

Спасибо за интерес к проекту! 🐻

## Как предложить изменение

1. Fork → ветка `feat/...` или `fix/...` (conventional commits: `feat:`, `fix:`,
   `docs:`, `refactor:`, `test:`, `chore:`).
2. Гейт перед пушем (всё должно быть зелёным):
   ```bash
   npx tsc --noEmit && npx eslint . && npx vitest run
   cd src-tauri && cargo fmt --all -- --check && cargo clippy --all-targets -- -D warnings && cargo test
   ```
3. PR-описание: что и зачем, скриншоты для UI-изменений (обе темы!).

## Правила проекта

- **Никаких захардкоженных строк интерфейса** — только ключи i18next в
  `src/i18n/{en,ru}.json` (RU и EN симметрично).
- **Обе темы равноправны** — любой UI-экран должен корректно выглядеть в тёмной
  и светлой; дизайн-токены — только через CSS variables (`src/index.css`).
- Аргументы процессам — **только массивами**; любой новый вход в argv проходит
  валидацию в Rust.
- Секреты/cookies не логируются.
- Тесты на парсеры и валидаторы обязательны (yt-dlp JSON, aria2 status, URL-роутер).
- DRM не поддерживается и не обходится — PRs с обходом защит отклоняются.

## Скиллы агентов

Если работаете с агентом: скиллы подключаются по процессу из SKILLS.md
(найти → проверить на безопасность → установить → применить → задокументировать).

## Локализация

Новые ключи добавляйте сразу в оба словаря; плюрализация — через суффиксы i18next
(`_one/_few/_many/_other` для RU). Даты/числа/размеры — только через `src/lib/format.ts`.
